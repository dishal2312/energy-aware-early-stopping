# Supporting Material – Energy-Aware Early Stopping

## 1. Overview

This folder contains the supporting material for the dissertation project on energy-aware early stopping for neural network training.

The project consists of two main stages:

1. **Step 1 – Baseline Training:** neural networks are trained under different configurations while recording training performance, execution time, and energy consumption.
2. **Step 2 – Decision Model:** the recorded training data is used to train models that predict whether training should continue or stop, based on the accuracy–energy trade-off. The learned approaches are compared with patience-based early-stopping baselines.

Both the original implementation and an extended V2 implementation are included.

## 3. Source Code

### `step1_baseline_training.py`

This is the original Step 1 implementation.

It trains MLP configurations on MNIST while varying the network architecture, learning rate and batch size. Training and validation performance, execution time and energy consumption are recorded.

The generated logs are stored in `training_logs/`.

### `step1_v2.py`

This is the extended Step 1 implementation.

It expands the experiments to four datasets:

- MNIST – MLP
- FashionMNIST – MLP
- CIFAR-10 – CNN
- SVHN – CNN

There are 160 experiment runs in total, with 40 runs for each dataset. The implementation also supports CUDA GPU execution when available and can resume an interrupted set of experiments by skipping runs whose CSV output already exists.

The generated logs are stored in `training_logs_v2/`.

### `step2_decision_model.py`

This is the original Step 2 implementation.

It loads the Step 1 training logs, labels epochs as `stop` or `continue` according to the energy–accuracy trade-off, trains a Random Forest classifier using Leave-One-Run-Out cross-validation, and compares the resulting stopping strategy with patience-based baselines.

The outputs are stored in `results/`.

### `step2_v2.py`

This is the extended Step 2 implementation.

In addition to Random Forest, it evaluates:

- Gradient Boosting
- Logistic Regression
- AdaBoost

The extended analysis includes:

- Leave-One-Run-Out cross-validation
- Per-dataset analysis
- Sensitivity analysis of the stopping threshold
- Standard-deviation reporting
- An ablation study comparing models with and without energy-related features
- Wilcoxon signed-rank statistical significance testing
- Additional plots and result tables

The outputs are stored in `results_v2/`.

## 4. Training Logs

### `training_logs/`

Contains the training logs produced by the original Step 1 implementation.

Individual `run_XXX.csv` files contain the recorded results for individual training runs. `all_runs_combined.csv` contains the combined training data.

### `training_logs_v2/`

Contains the training logs produced by the extended Step 1 implementation.

The 160 runs are organised as follows:

- Runs 1–40: MNIST
- Runs 41–80: FashionMNIST
- Runs 81–120: CIFAR-10
- Runs 121–160: SVHN

`all_runs_combined.csv` contains the combined training data used by the Step 2 V2 analysis.

## 5. Results

### `results/`

Contains the outputs from the original Step 2 analysis, including comparison plots, feature importance, an example learning curve, an energy–accuracy trade-off plot and the numerical results table.

### `results_v2/`

Contains the outputs from the extended Step 2 analysis.

These include overall comparison results, feature importance, energy–accuracy trade-offs, per-dataset results, sensitivity analysis, ablation results, statistical significance results, and supporting plots.

The CSV files contain the numerical results generated by the corresponding analyses.

## 6. Energy Measurement

Energy consumption is monitored during training using CodeCarbon when it is available.

The scripts use CodeCarbon's offline emissions tracker for energy measurement. If CodeCarbon cannot be imported, the training scripts use a time-based energy estimate instead.

`power_metrics_log.txt` contains the power/energy monitoring information generated during the project.

---

## 7. Datasets

The scripts use the following image-classification datasets:

- MNIST
- FashionMNIST
- CIFAR-10
- SVHN

The datasets are loaded using `torchvision`. They can be downloaded automatically by the scripts when they are not already available locally.

The downloaded datasets are not required to be included in this supporting-material submission because the scripts can obtain them when required.

## 9. Running the Code

All commands below should be run from the root of the supporting-material directory.

### Step 1 – Original Implementation

```bash
python code/step1_baseline_training.py
```

This generates the original training logs in:

```text
training_logs/
```

### Step 1 – Extended Implementation

```bash
python code/step1_v2.py
```

This generates the extended training logs in:

```text
training_logs_v2/
```

The extended version performs 160 training runs, each consisting of 30 epochs, so execution time depends on the hardware available. CUDA GPU execution is supported when available.

### Step 2 – Original Implementation

After the required Step 1 logs have been generated:

```bash
python code/step2_decision_model.py
```

This reads the training logs and generates results in:

```text
results/
```

### Step 2 – Extended Implementation

After `step1_v2.py` has completed:

```bash
python code/step2_v2.py
```

This reads:

```text
training_logs_v2/all_runs_combined.csv
```

and generates the extended analysis in:

```text
results_v2/
```

## 10. Existing Experimental Outputs

The supplied `training_logs`, `training_logs_v2`, `results`, and `results_v2` directories contain the outputs generated during the project.

These files are included so that the experimental data and results can be inspected without requiring the complete training process to be repeated.

Re-running the training scripts may produce slightly different execution-time and energy measurements depending on the hardware and software environment.

The V2 Step 1 implementation also checks whether an individual run CSV already exists and skips completed runs, allowing an interrupted experiment to be continued.
